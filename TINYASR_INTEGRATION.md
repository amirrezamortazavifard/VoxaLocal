## Core Engine Architecture

TinyASR implements a specialized on-device Automatic Speech Recognition architecture based on:
1. **Zipformer2 Transducer (RNN-T & TDT)**: A causal Zipformer2 encoder with stateless decoder and joint network.
2. **Dual-Pass Recognition**:
   - **Streaming First Pass**: 32-frame chunks at 50 Hz (64 feature frames, 640 ms) with 128 frames of left context. Streaming words are generated with greedy search for lowest latency.
   - **Full-Context Re-decoding Pass**: Every short pause and every 0.32 s of new audio, the uncommitted "open" sentence is re-decoded with full context, no attention mask, and beam search (default Beam Width = 4).
3. **Voice Activity Detection**: Built-in 16 kHz Silero VAD v5 to classify speech vs silence.
4. **End-of-Turn Head**: A trained classification head that predicts whether the speaker has completed their sentence ($P(\text{finish}) > 0.5$). Once triggered, the sentence ends, punctuation is finalized, and words are permanently committed.

## Key Rust APIs Used in VoxLocal

### 1. `tinyasr::Models::load`
```rust
pub struct Files<'a> {
    pub asr: &'a [u8],
    pub vad: &'a [u8],
}

let models = tinyasr::Models::load(tinyasr::Files {
    asr: &uncompressed_tzf,
    vad: &uncompressed_onnx,
})?;
```
Loads the neural network weights into memory. TinyASR keeps int4 weights packed in memory (~46 MB RAM footprint for the 38 MB model) and compiles SIMD matrix kernels for x86_64 AVX2 / AVX-512 VNNI.

### 2. `tinyasr::Models::set_threads`
```rust
models.set_threads(num_threads);
```
Configures the internal thread pool for parallel matrix products, multi-head attention, and layer blocks.

### 3. `tinyasr::Session` (Live Streaming)
```rust
let mut session = tinyasr::Session::new(&models, &["fa", "en"], tinyasr::Options {
    start_lang: "fa".to_string(),
    beam: 4,
    ..Default::default()
});

// Stream audio in any chunk size (e.g. 50ms to 320ms)
let events: Vec<tinyasr::Event> = session.push(&pcm_16k_mono);

// On stop:
let final_events: Vec<tinyasr::Event> = session.finish();
```

### 4. `tinyasr::Transcription` (Finished Audio Files)
```rust
let transcription = tinyasr::Transcription::new(&models, &audio_16k, &["fa", "en"], 4);
for piece in transcription {
    for word in piece {
        // word.text, word.start, word.end, word.join
    }
}
```

## Re-decoding & UI Event Protocol

The live recognition engine emits 4 primary event types:

```
┌─────────────────────────────────────────────────────────────┐
│                       tinyasr::Event                        │
├─────────────────┬──────────────────────┬──────────┬─────────┤
│     Commit      │       Partial        │ Language │   Eou   │
│  (Final Words)  │ (Open & Tail Words)  │ (Switch) │  (End)  │
└─────────────────┴──────────────────────┴──────────┴─────────┘
```

### Crucial UI Handling Rule
- **`Commit(words)`**: Words that have been finalized by the end-of-turn head or long silence. These words are **immutable** and appended to the permanent transcript history.
- **`Partial { open, tail }`**: Words that are still provisional:
  - `open`: Words generated by the full-context second-pass beam search.
  - `tail`: The newest provisional words from the streaming decoder.
  - **Rule**: Every incoming `Partial` event **completely replaces** the previous provisional transcript segment. It must never append duplicates to old partial text.
